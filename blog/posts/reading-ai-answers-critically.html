Reading AI answers with a critical eye

Nov 14, 2026 · 4 min read

LLMs are fluent. That is exactly why they are easy to over-trust. While building my local RAG agent, I collected the mistakes it made and turned them into a small "bug dojo": wrong answers I use to practise spotting problems. Here is the checklist that came out of it.

1. Does it cite a source?

An answer about code with no file path is an opinion. I only trust answers that point to where the code lives, and I open that file.

2. Does the source actually say that?

The most common failure was a real file cited for a claim it does not support. Retrieval found something nearby; the model filled the gap.

3. Is the version right?

Frameworks move fast. Class names and import paths change between releases, and models happily mix old and new APIs.

4. Would it run?

For any snippet, the fastest check is to run it. A five-second test beats a five-minute debate.

5. What did it leave out?

Answers can be correct and still incomplete: missing error handling, a config flag, or the one subclass that overrides everything.

A good AI assistant is one you can check. Build your tools so checking is easy.
